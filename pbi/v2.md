# V2 — Sosyal Döngü (İçerik Motoru)

> Index: [`README.md`](README.md) · Vizyon: `../vision.md` · Standart: `../CLAUDE.md`
> Durum: 🔭 Kapsam listesi — sırası gelince V1 detayına (user story + kabul + tech + DoD) açılacak.

**Hedef:** Anlık foto + ephemeral feed + kalıcı envanter ile app'i sosyal ağa dönüştürmek.

- **G-201** Anlık foto çekimi (galeriden değil, o an — Snap tarzı kamera akışı). Nav'daki ➕ butonu kameraya evrilir.
- **G-202** Ephemeral feed (24s sonra akıştan düşen postlar) — RLS `expires_at` filtresi
- **G-203** Ephemeral medya otomatik silme (`pg_cron` + storage/R2 temizliği). Açılırken:
  RLS `expires_at > now()` filtresi "kayboldu"nun tek doğruluk kaynağıdır, cron sadece
  storage geri kazanımıdır (gece → medya ~24s fazladan durabilir). Silme sırası tanımla
  (önce medya sonra satır, veya orphan reconciliation job'ı) ki yetim obje/satır kalmasın.
- **G-204** Envanter (kalıcı raf): anlık fotodan beslenen, profilde sergilenen eşya listesi. Profile "Envanter" sekmesi eklenir (G-84 genişler).
- **G-205** Envanter için bölüm bazlı görünürlük (G-22 modelini genişlet)
- **G-206** Reaksiyonlar (beğeni/emoji) ve temel etkileşim
- **G-207** Feed için medya pipeline: istemci sıkıştırma (WebP ~250KB) + R2 entegrasyonu
- **G-208** Keşfet/arama genişletme (public profiller, envanter vitrinleri)
- **G-209** İçerik şikayeti (G-73 report'un feed'e genişlemesi)
- **G-210** Home → feed + dashboard birleşimi (G-82 evrimi)
- **G-211** Link'ten zengin ürün kartı (OG metadata) — detay aşağıda (erken açıldı;
  Kuzey V2'de denemek istiyor). **V4 G-401 kataloğuna ara basamak.**
- **G-212** App-dışı kişiden alınan hediyeyi kaydetme — detay aşağıda (erken açıldı).

**G-212 — App-dışı kişiden alınan hediye kaydı** 🟡
- *User story:* Üye olmayan birinden (babam, iş arkadaşım…) hediye aldığımda bunu
  kendi hediye geçmişime elle ekleyebilmek isterim — geçmişim yalnız üyelerin
  kaydettikleriyle sınırlı kalmasın.
- *Kabul kriterleri:*
  - Gifts → Aldıklarım sekmesinde "hediye ekle" aksiyonu: kimden (serbest metin,
    ör. "Babam"), hediye, tarih, isteğe bağlı not.
  - Kayıt Aldıklarım listesinde diğerleriyle birlikte, kimden etiketiyle görünür;
    etiket profile LİNK DEĞİLDİR (üye değil) — görsel olarak ayırt edilir.
  - Sürpriz mekaniği YOK (kendi kaydın, zaten biliyorsun); reveal alanları boş.
  - Hediye-geçmişi görünürlük kuralına tabi (arkadaşlar geçmişini görebiliyorsa
    bunu da görür).
  - Kendi eklediği kaydı silebilir/düzenleyebilir; başkasının verdiği kayıtlara
    dokunamaz (mevcut kural).
  - G-52 arkadaş-geçmişi ve G-62 suppress-if-gifted sorguları etkilenmez
    (onlar giver_id üzerinden çalışır; external kayıtlar giver_id=null).
- *Teknik notlar:*
  - Şema: `gifts.giver_label text` (nullable, ≤80). İki giver durumu netleşir:
    `giver_id` dolu = üye; `giver_id null + giver_label dolu` = app-dışı;
    ikisi de null = silinmiş üye (mevcut anonimleştirme). CHECK: giver_id ile
    giver_label aynı anda dolu olamaz.
  - RLS: mevcut insert policy giver-taraflı (`giver_id = auth.uid()`); ek policy:
    `recipient_id = auth.uid() AND giver_id IS NULL` (kendine external kayıt).
    Update/delete: external kayıtlar için recipient'a izin (`recipient_id =
    auth.uid() AND giver_id IS NULL`); üye-verdiği kayıtlarda mevcut giver-only
    kural sürer.
  - UI: Aldıklarım boş-durumu da bu aksiyona yönlendirir ("İlk hediyeni ekle");
    giver_label satırda "Babam" gibi düz metin, avatar yerine nötr ikon.
  - Anonim "Birisi" fallback'i (silinmiş üye) ile external etiket karışmamalı —
    ayrı render yolları.
- *DoD:* Migration + pgTAP (external insert/update/delete + üye-kayıtlarına
  dokunamama + görünürlük) + widget testleri (ekle/boş-durum/listede render) +
  iki dilde string + iki temada görsel kontrol.

**G-211 — Link'ten zengin ürün kartı (OG metadata)** 🟡
- *User story:* Wishlist'ime veya hediye kaydına bir ürün linki yapıştırdığımda, düz
  metin yerine ürünün adını/görselini/fiyatını gösteren bir kart görmek isterim —
  uygulama "text app" gibi değil, gerçek ürünlerle çalışıyormuş gibi hissettirsin.
- *Kabul kriterleri:*
  - Wishlist ekleme ve hediye kaydetme formlarındaki link alanına URL yapıştırılınca
    önizleme otomatik denenir (debounce'lu); başlık + görsel + (varsa) fiyat kart
    olarak formda görünür ve kayıtla birlikte saklanır.
  - Kart; wishlist listesinde, arkadaşın wishlist görünümünde ve hediye satırlarında
    render edilir (görsel + başlık; dokununca link harici tarayıcıda açılır).
  - **Zarif düşüş:** metadata alınamazsa (timeout, engelli site, OG yok) form serbest
    metin davranışına döner — hata kullanıcıyı bloklamaz, sessiz bilgi notu yeter.
  - Önizleme kullanıcı tarafından kaldırılabilir ("kartsız kaydet").
  - Boş/geçersiz URL'de önizleme denenmez; http(s) dışı şemalar reddedilir.
- *Teknik notlar:*
  - Fetch **sunucuda** (Edge Function `link-preview`): SSRF koruması (yalnız http/https,
    IP-literal/localhost/özel ağ reddi, redirect limiti), timeout (~5s), yanıt boyut
    limiti (~1MB), sadece `text/html` parse.
  - OG/Twitter-card metadata parse: `og:title`, `og:image`, `og:price:amount` +
    yaygın fiyat fallback'leri; site adı `og:site_name`/host.
  - Görsel **R2'ye kopyalanır** (hotlink kırılganlığı + izleme pikseli riski);
    WebP'ye sıkıştır (~100KB, G-207 pipeline'ını kullan).
  - Şema: `link_previews` tablosu (url_hash PK, url, title, image_path, price,
    site, fetched_at) — aynı URL tekrar çekilmez (cache + G-401 için popülerlik
    sinyali); `wishlist_items`/`gifts` → nullable `link_preview_id` FK.
  - Rate limit: kullanıcı başına dakikada ~10 önizleme (enumeration/istismar önlemi).
  - RLS: `link_previews` herkese-okunur değil; yalnız ilişkili satırı görebilen okur
    (mevcut can_view_* zincirinden türet).
- *DoD:* Uygulandı + Edge Function birim testleri (SSRF/parse/fallback) + widget
  testleri (kartlı/kartsız/düşüş durumları) + RLS pgTAP + lint temiz + iki dilde
  string'ler + her iki temada görsel kontrol (design.md).
